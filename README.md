Прозрачная вакансия

О проекте

«Прозрачная вакансия» — прототип системы автоматического анализа вакансий Калининградской области из открытого API портала «Работа в России».

Система проверяет, насколько понятно соискателю описаны условия труда, выявляет пропуски, неоднозначные формулировки и противоречия, а затем формирует JSON-отчёт с конкретными рекомендациями по улучшению текста вакансии.

Проект ориентирован на регион Калининградская область (код региона — 39).

Технологический стек

Python 3.10+
Requests — получение данных через HTTP API.
Ollama — локальный запуск языковой модели.
Qwen 2.5 3B — анализ неоднозначных формулировок.
JSON — входные данные, настройки и итоговый отчёт.
Windows Task Scheduler — автоматический запуск по расписанию.
ИИ работает локально, без платного API-ключа.

Что проверяет система

Анализ выполняется по семи основным категориям:
Название должности — наличие и понятность названия вакансии.
Обязанности — наличие конкретного описания работы.
Требования — наличие содержательных требований к кандидату.
Оплата труда — наличие информации о заработной плате.
График работы — наличие понятных сведений о режиме работы.
Место работы — наличие информации о месте выполнения работы.
Тип занятости — наличие сведений о характере занятости.
Дополнительно анализируются неоднозначные формулировки и возможные противоречия между полями вакансии.

Как работает анализ

Система получает вакансии через API «Работа в России».
Извлекает текстовые и структурированные поля.
Выполняет проверки заполненности и набор правил.
Передаёт подходящие данные локальной модели Qwen 2.5 3B через Ollama для дополнительного анализа.
Проверяет полученные замечания, в том числе соответствие цитат исходным данным.
Объединяет результаты и формирует JSON-отчёт.
Результаты ИИ проходят проверку перед добавлением в отчёт. Если Ollama недоступна, сохраняются результаты проверок по правилам.
Установка на Windows
Установить Python 3.10 или новее.

Установить Ollama: https://ollama.com/download

Открыть PowerShell в корневой папке проекта.
Создать виртуальное окружение и установить зависимости:

py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

Скачать локальную модель:
ollama pull qwen2.5:3b

Проверить работу модели:
ollama run qwen2.5:3b

Ollama должна быть доступна по адресу http://localhost:11434.

Запуск программы
Рабочий режим — получение вакансий из API
python main.py --api --limit 200
Система загружает до 200 вакансий Калининградской области.

Параметры API:

размер страницы — 100 записей;
максимальный размер страницы — 100 записей;
для получения следующих страниц используется параметр offset.
Проверочный режим — локальный JSON
python main.py --input organizer_sample.json
Этот режим использует локальные тестовые данные и не обращается к API портала.

Проверочный режим без ИИ

python main.py --input organizer_sample.json --no-ai
Позволяет проверить работу правил без запуска языковой модели.

Настройки

Основные параметры находятся в config.json:

api_url — адрес API;
page_size — размер страницы;
max_vacancies — максимальное количество вакансий;
request_timeout — тайм-аут HTTP-запросов;
report_path — путь к итоговому отчёту;
ollama.enabled — включение или отключение ИИ;
ollama.base_url — адрес Ollama;
ollama.model — используемая модель;
ollama.timeout — время ожидания ответа модели;
automation.enabled — включение автоматизации;
automation.task_name — название задачи Windows;
automation.schedule — тип расписания;
automation.start_time — время ежедневного запуска.

Формат отчёта

Результат сохраняется в reports/report.json.

Основная структура:

{
  "vacancies": [
    {
      "id": "ID вакансии",
      "url": "Ссылка на вакансию",
      "issues": [
        {
          "topic": "Категория замечания",
          "source_field": "Исходное поле",
          "quote": "Цитата из вакансии",
          "problem": "Описание проблемы",
          "recommendation": "Рекомендация"
        }
      ]
    }
  ]
}

Если проблем не обнаружено, поле issues содержит пустой массив.

Для отсутствующих данных цитата может быть пустой. Для замечаний о противоречиях учитываются соответствующие исходные значения.

Автоматический запуск в Windows

Для автоматизации предусмотрены PowerShell-скрипты:

scripts/register_scheduled_task.ps1 — регистрация ежедневной задачи;

scripts/remove_scheduled_task.ps1 — удаление задачи.

В config.json необходимо включить автоматизацию:

"automation": {
  "enabled": true,
  "task_name": "TransparentVacancy-Daily",
  "schedule": "DAILY",
  "start_time": "09:00"
}

Регистрация задачи выполняется из корневой папки проекта:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\register_scheduled_task.ps1

Для проверки регистрации:

Get-ScheduledTask -TaskName "TransparentVacancy-Daily"

Для ручного запуска зарегистрированной задачи:

Start-ScheduledTask -TaskName "TransparentVacancy-Daily"

Для удаления задачи:

.\scripts\remove_scheduled_task.ps1

В текущей реализации поддерживается ежедневное расписание DAILY. Планировщик запускает рабочий режим main.py --api.

Надёжность и обработка ошибок

Повторные вакансии с одинаковым ID не дублируются в итоговом отчёте.

При временных ошибках соединения выполняются повторные запросы.

Если API недоступен, предыдущий успешный отчёт сохраняется.

Локальный проверочный режим не обращается к API.

При ошибке Ollama сохраняются результаты проверок по правилам.

Результаты анализа сохраняются в JSON.

Ограничения MVP

Полнота анализа зависит от качества и заполненности исходных данных API.

Локальная языковая модель может допускать смысловые ошибки.

Проверка цитаты подтверждает её наличие в исходном поле, но не гарантирует правильность смыслового вывода.

Замечания системы являются рекомендациями по улучшению текста вакансии, а не юридической оценкой работодателя или вакансии.
